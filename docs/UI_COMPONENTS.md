# UI Components

Read this before creating or changing UI. Reuse what is listed here; see every component live at `/docs/library` (logged in). Props live in the code, not here.

## Tokens

Defined once in `resources/css/app.css` (`@theme`), from the prototype's `:root`. Use them as Tailwind colors (`bg-panel`, `text-primary`, `border-line`):

- Surfaces: `bg`, `panel`, `panel-2`, `line`
- Text: `text`, `muted-text`, `on-primary`
- Brand: `accent`, `accent-deep`, `primary`, `primary-soft`, `primary-shadow` (the dark edge under headings)
- Categories: `research`, `tooling`, `docs`, `experiment`
- Difficulty: `easy`, `medium`, `hard`
- Status: `status-open`, `status-open-line`, `status-review`
- Fonts: `font-brand` (Cinzel: app name, big headings), `font-title` (Cormorant Garamond: section headings, quest titles, tabs), `font-sans` (Figtree: everything else)

The surface, text and brand tokens are the fallback palette. The real values come from the active theme preset in `config/branding.php`, which `app.blade.php` writes into `<head>` after the CSS, so never hard-code a colour or an `rgb(...)` of the palette: use the token, or `color-mix(in_srgb,var(--color-accent)_35%,transparent)` for a tint. Category, difficulty and status colours do not change with the preset.

The shadcn variables (`background`, `primary`, `muted`, `border`, `ring`, …) are mapped onto these tokens, so shadcn components already look right.

## shadcn components (`@/components/ui/*`)

Use these directly for generic UI: `button`, `badge`, `dialog`, `dropdown-menu`, `tabs`, `select`, `switch`, `progress`, `input`, `label`, `checkbox`, `skeleton`, `tooltip`, `sonner` (toasts). They are restyled with the tokens; change the shared look in the component file, not with one-off overrides.

Layouts (chosen in the `app.tsx` layout resolver): app pages use `@/layouts/app-layout` (PageHero + PlayerCard + AppNav); `/docs/*` pages use `@/layouts/docs-layout` (PageHero with a back link, no app nav); `auth/*` pages use `@/layouts/auth-layout` (the prototype login screen: art background, crest card, mascot).

Form fields (auth screens and Settings): `@/components/password-input` (show/hide, optional left `icon`) and the field styles in `@/lib/form-styles` (`fieldInputClassName`, `fieldReadOnlyClassName`, `fieldLabelClassName`). `SectionHeading` takes `tone="primary"` for Settings section titles. | Component          | Import path                              | Purpose                                                                                                                                                               |
| ------------------ | ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `QuestActionPanel` | `@/components/quests/quest-action-panel` | The quest page action panel: XP reward on top, then Accept / Edit / Delete, Turn in / Drop, "Claimed by", In review, or "Completed by", by status and the `can` flags |

Delete and Drop ask for confirmation in the shadcn `dialog`. The panel reads `can` and `acceptBlockedReason` from the server and decides nothing itself.

Helpers: `@/lib/assets` (`assets.mascots.notFound`, `portraitUrl(n)`) so components never hard-code fixed image paths. Editable header and mascot art come from `usePage().props.branding` (`header_url`, `mascots`); the logo, banner and app name also come from the same prop (`logo_url`, `banner_url`, `name`), since an admin can change them. `@/lib/quest-icons` has `categoryIcons`, `statusIcons` and `difficultyIcons` (one icon per category, status and difficulty); use them instead of picking icons again. `@/lib/badges` has `badgeLook` (icon and colour per badge key) and `progressText(badge)` (the locked text, e.g. "2 / 3 research"); feed `AchievementBadge` from a `BadgeProgress` row with them. `@/lib/generate-password` has `generatePassword()` (16 characters; passes the strongest server rule) and `describePasswordRules(rules)` (help text from the server's rule string); admin password fields use them.

## shadcn or game component?

- Generic controls (buttons, menus, dialogs, form fields, tabs) → shadcn from `@/components/ui`.
- Anything specific to quests, people, XP, levels, or badges → a game component. If none fits, extend an existing one before adding a new one.
- Never show status, category, or difficulty by color alone; the game components always include text.
- Game components take data through props only: no data fetching and no permission logic inside them.

## Naming

- File: `resources/js/components/game/kebab-case.tsx`
- Export: a named PascalCase component (`export function QuestCard`), with typed props and an explicit return type
- Sample data for the library page lives in `resources/js/data/library-mock.ts` and is never imported by real pages

## Adding or changing a shared component

In the same task:

1. Build or change the component.
2. Add or update its section on `/docs/library` (`resources/js/pages/docs/library.tsx`).
3. Add or update its row in this file.
